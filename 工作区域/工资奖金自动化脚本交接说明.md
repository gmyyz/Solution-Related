# 工资奖金自动化脚本交接说明

本文档用于帮助后来者快速理解 `工作区域/运行-1.工资单首步处理.pyw` 的运行逻辑、所需文件、A1-A10 十张凭证的生成规则，以及关键数字如何勾稽。

当前版本已不再把所有逻辑都堆在单一 `.pyw` 文件里，而是改成“薄入口 + 模块包”的结构。

## 1. 脚本目标

这套脚本的目标是：

1. 从 HR 原始工资单出发，自动完成工资表整理。
2. 自动匹配成本中心、内部订单，并核对银行流水。
3. 自动生成 SAP 可导入的标准总账凭证模板。
4. 按公司、按凭证类型分别输出结果文件。

## 1.1 当前入口与模块结构

当前启动入口仍然是：

- `工作区域/运行-1.工资单首步处理.pyw`

但这个文件现在只负责启动，真正逻辑已经拆到：

- `工作区域/payroll_tool/gui.py`
- `工作区域/payroll_tool/pipeline.py`
- `工作区域/payroll_tool/core.py`
- `工作区域/payroll_tool/options.py`
- `工作区域/payroll_tool/contexts.py`
- `工作区域/payroll_tool/vouchers.py`
- `工作区域/payroll_tool/validation.py`

可按下面理解：

- `gui.py`：桌面界面、日志、按钮、公司/凭证选择
- `pipeline.py`：运行入口，负责把 GUI 选项传给主流程
- `core.py`：当前业务主实现，负责工资单整理、凭证生成、输出写入
- `options.py`：公司与凭证选择定义、预设组合、按需文件规则
- `contexts.py / vouchers.py / validation.py`：按领域分组的模块入口，便于后续继续拆细

当前已覆盖的凭证范围：

- `A1` 社保扣款凭证
- `A2` 公积金扣款凭证
- `A3` 工资扣款凭证
- `A4` 上月实际工资入账
- `A5` 当月工资计提
- `A6` 研发工时分摊调整
- `A7` 年终奖计提
- `A8` 年终奖分摊
- `A9` CO工单分摊
- `A10` 研发费用分摊

## 2.2 公司代码

固定有两家公司：

- `耐数电子` -> `2050`
- `耐数信息` -> `2060`

其中：

- `A1-A8`：2050、2060 都可能生成
- `A9`：只有 `2050` 生成
- `A10`：2050、2060 都生成

## 2.3 原始文件保护原则

脚本原则上只读取原始源文件，不直接修改原始文件格式。

特别注意：

- `年终奖计提2026_ - to财务.xlsx` 现已按只读模式加载，不允许回写。
- `工时数据.xlsx` 主流程中只做读取和内存匹配，不保存回源文件。
- 生成结果全部写到输出文件，不覆盖原始模板和原始数据。

## 3. 整体运行顺序

脚本的主流程按以下顺序执行：

1. 读取工资单、Mapping 表、工时数据、年终奖数据、银行流水。
2. 对工资单 `A/B` 列空白单元格向下填充，到“总计”行停止。
3. 校验工资单每一行 `Q列` 实发金额。
4. 生成工资单 `S列 成本中心`、`T列 内部订单`。
5. 若有内部订单未匹配成功，则直接终止。
6. 按公司拆分工资整理文件。
7. 生成 `A1-A4` 实际凭证。
8. 生成 `A5-A6` 计提凭证。
9. 生成 `A7-A8` 年终奖凭证。
10. 如果存在 `CO工单分摊.xlsx`，额外生成 `A9`。

## 3.1 运行时可选项

当前 GUI 已支持在运行前直接选择：

- 公司：`2050 耐数电子`、`2060 耐数信息`
- 凭证：`A1-A10` 任意多选
- 快捷组合：`A1-A4`、`A5-A6`、`A7-A8`、`A9`、`A10`、`全选`

运行规则：

- 未选公司，不生成对应公司的整理后工资表和凭证
- 未选凭证，不生成对应凭证文件
- 如果某类凭证未被选中，则对应输入文件不再强制要求
- 若只选部分凭证，则跨凭证校验会按所选范围自动收缩

## 5. 工资整理文件逻辑

脚本首先会输出按公司拆分的工资整理文件，例如：

- `耐数电子/2603/2月工资单-整理后.xlsx`
- `耐数信息/2603/2月工资单-整理后.xlsx`

该文件包含以下关键处理：

## 5.1 A/B 列填充

- 按上一行非空值向下填充
- 到“总计”行停止
- 不越界，不改原格式样式

## 5.2 Q 列校验

每一行都校验：

`Q列实发金额 = E列税前金额 - K:P列个人承担金额`

若不相等：

- 输出文件对应行标红

## 5.3 S/T 列生成

- `S列`：成本中心
- `T列`：内部订单

来源规则：

- 成本中心来自 `Mapping表.xlsx`
- 内部订单来自 `工时数据.xlsx`
- 若项目为空白，则按“部门 + 日常工作”去匹配
- `NAISHU SOLUTION` 等同 `OSD运营支持部`
- 工资单里 `劳务费` 行也要求匹配内部订单

若未匹配成功：

- 输出文件标红
- 主流程直接终止

## 6. 银行流水核对逻辑

银行核对分四类：

## 6.1 实发工资

核对关系：

`工资单 Q列汇总`  
=  
`次月银行流水中所有“代发工资”记录的 O 列组合金额`

说明：

- 支持最多 5 笔组合匹配
- 不是只取单笔

## 6.2 公积金

核对关系：

`工资单 J列 + N列汇总`  
=  
`当月银行流水中 Payment Name = 北京住房公积金管理中心 的 O 列金额`

特殊规则：

- `2050 / 202602` 允许差额 `3650`

## 6.3 个税

核对关系：

`工资单 O列汇总`  
=  
`次月银行流水中 国家金库北京市分库 两条记录里金额较小的一条`

## 6.4 社保

核对关系：

`工资单 F:I + K:M 七列汇总`  
=  
`次月银行流水中 国家金库北京市分库 剩余那条较大金额记录`

## 7. A1-A10 凭证逻辑

## 7.1 A1 社保扣款凭证

用途：

- 支付工资所属期间社保

借方：

- 七条应付职工薪酬社保科目
- 分别来自工资表总计行：
  - 公司承担养老
  - 公司承担失业
  - 公司承担工伤
  - 公司承担医疗
  - 个人承担养老
  - 个人承担失业
  - 个人承担医疗

贷方：

- 银行流水对应社保的银行科目
- 按实际流水逐行展开
- 银行行项目 `P列原因代码` 固定填写 `204`

关键勾稽：

`A1借方合计 = A1贷方合计 = 工资表社保汇总 = 银行社保流水`

## 7.2 A2 公积金扣款凭证

用途：

- 支付公积金

借方：

- `2211070001`
- `2211070002`

贷方：

- 银行流水中 `北京住房公积金管理中心` 对应银行科目
- 银行行项目 `P列原因代码` 固定填写 `204`

关键勾稽：

`工资表 J+N`  
对比  
`银行公积金流水`

特殊月份：

- `2050 / 202602` 允许差额 `3650`

## 7.3 A3 工资扣款凭证

用途：

- 支付实发工资、劳务费、个税

借方：

- 劳务费：`6601110001`
- 个税：`2221070000`
- 薪酬：`2211010001`

说明：

- `劳务费` 按工资表逐行展开
- 每条劳务费带 `J列成本中心`、`K列内部订单`

贷方：

- 代发工资组合的银行科目
- 个税流水对应银行科目
- 银行行项目 `P列原因代码` 固定填写 `204`

关键勾稽：

- 非劳务 `Q列汇总` -> `2211010001`
- 非劳务 `O列汇总` -> `2221070000`
- 银行侧必须匹配“工资组合 + 个税国库行”

## 7.4 A4 上月实际工资入账

用途：

- 把上月实际工资费用正式入账

借方：

- 工资、养老、失业、工伤、医疗、公积金费用
- 按 `成本中心 + 内部订单` 维度展开
- 排除 `劳务费`

贷方：

- 九个社保/公积金应付科目
- `2221070000` 个税
- `2211010001` 实发工资
- `2211010001` 其他项目

特殊逻辑：

- `OSD运营支持部` 且工时项目类型为“自研”时
- 内部订单按 `OSD运营支持部日常工作` 处理

关键勾稽：

- `A4` 自身借贷必须平
- `A1-A4` 之间重点往来科目要交叉对冲

## 7.5 A5 当月工资计提

用途：

- 按权责发生制，计提当月工资费用

借方：

- 与 A4 同口径
- 但只到 `成本中心`，不拆 `内部订单`

贷方：

- 与 A4 同口径

关键勾稽：

`A5总额 = A4总额`

## 7.6 A6 研发工时分摊调整

用途：

- 把 A5 中非 OSD 的费用重新按项目工时分摊到内部订单

贷方：

- 先冲回 A5 原借方费用
- 科目不变
- 成本中心不变
- 内部订单为空

借方：

- 按部门内各项目工时比例分摊到内部订单
- 成本中心沿用原部门成本中心

工时规则：

- 只看处理月份当月工时
- 只统计 `K > 0`
- `OSD运营支持部` 不参与分摊

关键勾稽：

`A6冲回金额 = A6分摊金额`

尾差处理：

- 分摊金额统一保留两位小数
- 尾差回补到最后一个内部订单

## 7.7 A7 年终奖计提

用途：

- 按成本中心计提年终奖

借方：

- 统一为 `6601010003`

贷方：

- 统一为 `2211010001`
- 每家公司只放一行汇总

金额规则：

- 季度末：取 `1-当月累计奖金`
- 非季度末：取 `当月奖金`
- 再乘 `当月奖金系数`
- 系数不追溯以前月份

示例：

- 3 月 -> `1-3月累计 × 3月系数`

## 7.8 A8 年终奖分摊

用途：

- 将 A7 的年终奖费用按工时分摊到内部订单

贷方：

- 冲回 A7 的非 OSD 奖金费用

借方：

- 按内部订单重新展开

工时规则：

- 1 月：只看 1 月工时
- 2 月：只看 2 月工时
- 3/6/9/12 月：看 1-当月累计工时
- `OSD` 不参与分摊

关键勾稽：

`A8分摊前总额 = A8分摊后总额`

## 7.9 A9 CO工单分摊

用途：

- 将待分摊费用按 CO 工单比例重新分配

适用范围：

- 仅 `2050`

来源文件：

- `耐数电子/处理月份/CO工单分摊/CO工单分摊.xlsx`

工作表 1：`CO工单分摊`

- `G列 != 0` 的明细行参与分摊
- 最后一行加总只做校验，不参与比例
- 分摊比例按参与分摊明细行的 `E列 实际成本借方`
- `A列` 作为借方内部订单

工作表 2：`待分摊费用`

- `A列`：贷方会计科目
- `D列`：待分摊金额

贷方固定规则：

- 记账码 `50`
- 成本中心 `20502020`
- 内部订单 `9201856`
- `O列反记账` 固定填写小写 `x`

借方固定规则：

- 记账码 `40`
- 成本中心留空
- 内部订单 = `CO工单分摊` sheet 的 `A列`

借方科目映射：

- 以下成本要素 -> `5001010011`
  - `6601010001`
  - `6601030002`
  - `6601030003`
  - `6601030005`
  - `6601030006`
  - `6601030008`
- 其余成本要素 -> `5001010012`

关键勾稽：

- `CO工单分摊` 明细 `G列合计` 必须等于最后一行加总
- `A9借方合计 = A9贷方合计`
- 借方金额按比例分摊并保留两位小数
- 尾差回补到最后一个订单

## 7.10 A10 研发费用分摊

用途：

- 将待分摊费用按研发工时重新分摊到内部订单

适用范围：

- `2050`
- `2060`

来源文件：

- `原始数据/待分摊费用/待分摊费用YYMM.xlsx`

基础字段：

- `E列`：公司代码，区分 `2050/2060`
- `J列`：会计科目
- `L列`：金额，先按 `费控科目 + 部门` 聚合后再作为分摊净额
- `S列`：成本中心编码
- `T列`：成本中心文本/部门文本，仅作辅助参考
- `U列`：原内部订单

聚合规则：

- `A10` 不是按待分摊费用每一行直接分摊
- 先按 `费控科目 + 部门` 聚合 `L列`
- 同组内正负金额先相互抵减，再按聚合后的净额分摊
- 若聚合后金额为 `0`，则该组跳过，不生成凭证行

贷方规则：

- 分组 `A10`
- 凭证类型 `SA`
- 记账码 `50`
- 会计科目取 `J列`
- 金额取聚合后的净额
- 成本中心取 `S列`
- 内部订单取 `U列`

借方规则：

- 分组 `A10`
- 凭证类型 `SA`
- 记账码 `40`
- 会计科目沿用原费用科目，即仍取 `J列`
- 金额按聚合后的净额，依据研发工时分摊到各内部订单
- 金额按工时比例分摊
- 成本中心默认沿用原成本中心
- 内部订单改为工时分摊后的项目订单

分摊口径：

- 绝不跨公司分摊
- 默认在部门内分摊
- 分摊月份只看处理月份当月工时
- `OSD` 不参与分摊

部门匹配逻辑：

- 不直接信任待分摊费用里的名称文本
- 先用 `S列成本中心编码`
- 再通过 `Mapping表.xlsx` 反查标准部门
- 再去 `工时数据.xlsx / 工时汇总 / E列部门` 取工时比例

特殊规则：

- `LHD硬件逻辑部` 与 `HLD硬件逻辑部` 视为同一部门
- `HLD硬件逻辑部` 分摊时，`9201856` 不进入分母，也不作为分子
- `2050 / 20502050`
  - 贷方冲销维持原成本中心 `20502050`
  - 借方分摊时视为 `20502060` 的工时口径
- `2060 / 20602020`
  - 若本部门当月找不到可用工时
  - 则改按整个 `耐数信息` 公司当月全部工时比例分摊

文本规则：

- 统一写为 `根据研发工时分摊YYYY年M月研发费用`

关键勾稽：

- `A10借方合计 = A10贷方合计`
- 每一行原费用科目在借方分摊后的合计，必须等于该行贷方冲销金额
- 所有拆分结果保留两位小数
- 尾差回补到最后一个内部订单

## 8. 跨凭证勾稽关系

## 8.1 A1-A4 重点科目对冲

脚本会对以下科目做 A1-A4 跨凭证检查：

- `2211060002`
- `2211030002`
- `2211040001`
- `2211020002`
- `2221070000`
- `2211010001`
- `2211060001`
- `2211030001`
- `2211020001`

其中：

- `2211010001` 会扣除“其他项目”那一行后再对冲

## 8.2 A5/A6 勾稽

- A5 先计提
- A6 再冲回并重新分摊

要点：

`A5原计提金额 = A6冲回金额 = A6重新分摊金额`

## 8.3 A7/A8 勾稽

- A7 先按成本中心计提
- A8 再按内部订单分摊

要点：

`A7分摊范围内金额 = A8冲回金额 = A8重新分摊金额`

## 8.4 A9 勾稽

- 待分摊费用总额 = A9 贷方总额
- 借方按订单分摊后总额必须完全一致

## 8.5 A10 勾稽

- 待分摊费用各行贷方金额 = 对应借方分摊后金额
- `A10` 整体借方合计 = 贷方合计
- 特殊成本中心转换只改变借方分摊口径，不改变贷方原始冲销口径

## 9. 尾差处理规则

所有涉及按比例拆分的凭证，统一采用以下原则：

1. 每笔拆分结果保留两位小数。
2. 先逐笔四舍五入。
3. 统计拆分后合计与原金额差异。
4. 若有尾差，则回补到最后一个分摊对象。

当前使用该规则的主要凭证：

- `A4`
- `A6`
- `A8`
- `A9`
- `A10`

## 11. 运行失败时优先检查什么

若脚本报错，优先检查以下几项：

1. 工资单目录下是否只有 1 份符合命名规则的原始工资单。
2. `Mapping表.xlsx` 是否存在。
3. `工时数据.xlsx` 是否存在且全部项目都能匹配到内部订单。
4. `年终奖计提2026_ - to财务.xlsx` 是否存在。
5. 银行流水目录下是否存在对应月份文件。
6. `CO工单分摊.xlsx` 是否存在、sheet 名是否正确、明细 `G列` 与最后一行加总是否一致。
7. `待分摊费用YYMM.xlsx` 是否存在，且 `E/J/L/S/U` 等关键列有值。
8. 是否存在借贷不平，尤其是比例分摊后的尾差问题。
