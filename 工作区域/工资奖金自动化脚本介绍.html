工资奖金自动化脚本介绍

本脚本面向财务月度工资奖金业务场景，能够从 HR 原始工资表出发，自动完成数据整理、映射校验、银行流水核对、SAP 标准凭证生成及公司拆分输出。 它不仅减少了手工汇总与重复检查的工作量，也把关键财务逻辑固化进脚本中，确保处理过程可重复、可追溯、可校验。当前版本还支持在运行前直接选择公司和 A1-A10 凭证子集，并先做启动页预检，不必每次都全量生成后才发现基础数据有问题。

新增：可选生成与模块结构

当前入口仍然是 `运行-1.工资单首步处理.pyw`，但实际逻辑已经拆到 `payroll_tool` 模块包中。GUI 现在支持直接勾选公司和凭证范围， 例如只生成 `2050 + A1-A4`、`2060 + A5-A6`、`A10` 等组合；未选凭证不会生成空文件，对应不需要的输入文件也不再强制校验。

运行入口

`运行-1.工资单首步处理.pyw` 现在只负责启动 GUI，避免所有逻辑继续堆在一个文件里。

模块分层

`gui.py` 负责界面与日志，`pipeline.py` 负责调度，`core.py` 负责当前主业务实现，`options.py` 管理选择项与预设组合。

可选生成

支持选择 `2050/2060` 两家公司，以及 `A1-A10` 任意组合；常用快捷组合为 `A1-A4`、`A5-A6`、`A7-A8`、`A9`、`A10`。

校验收缩

只选部分凭证时，系统会自动收缩校验范围；例如未完整选择 `A1-A4` 时，不再强制执行这四张凭证的跨组对冲校验。

启动页预检

启动页新增 `检查当前选择` 按钮，会在正式运行前先做只读预检，提前展示工资单公式、S/T 匹配、银行核对、工时/KOK3、奖金、CO、A10 待分摊等支撑结果。

局部刷新

切换公司、凭证或快捷组合时，不再整页销毁后重建，而是局部刷新资料清单和运行按钮状态，减少 Windows 下明显的白色闪屏。

第一部分：A1-A10 凭证逻辑与校验规则

为便于快速汇报与复核，下面将 A1-A10 各张凭证的用途、取数逻辑、分摊口径、文本规则与核心校验点集中展示。 阅读这一部分时，不需要先理解脚本代码，只需按凭证编号逐张查看即可快速把握整套自动化方案。

A1 社保扣款凭证

支付工资期间社保，借方挂应付社保，贷方逐笔展开银行流水。

  • 借方：公司/个人承担养老、失业、工伤、医疗，对应应付职工薪酬科目。
  • 贷方：取次月银行流水中社保对应国库流水的银行科目，按实际流水逐行展开。
  • 日期：取匹配银行流水中的最后交易日期。
  • 校验：工资表社保 7 列汇总必须与银行社保流水严格一致。

A2 公积金扣款凭证

支付公积金，借方按个人/公司对半拆分，贷方逐笔展开公积金流水。

  • 借方：`2211070001` 与 `2211070002`，按银行公积金总额拆分。
  • 贷方：取银行流水中“北京住房公积金管理中心”对应银行科目，按实际流水逐行展开。
  • 日期：取公积金流水最后交易日期。
  • 校验：工资表公司+个人公积金应与对应月份银行公积金流水一致，特殊月份按预设差额规则处理。

A3 工资扣款凭证

支付实发工资、劳务费与个税，工资流水支持多笔组合匹配。

  • 借方：劳务费、个人所得税、应付职工薪酬-薪酬。
  • 贷方：次月银行流水中匹配实发工资组合 + 个税流水，按银行流水逐行展开。
  • 日期：工资流水组合与个税流水中的最后交易日期。
  • 校验：Q 列实发金额与代发工资组合匹配；个税与国库较小金额流水匹配。

A4 上月实际工资入账

按成本中心 + 内部订单计提实际发生的工资相关费用，排除劳务费。

  • 借方：工资、养老、失业、工伤、医疗、公积金费用，按成本中心 + 内部订单展开。
  • 贷方：应付社保、公积金、个税、实发工资、其他项目。
  • 日期：处理月份最后一天。
  • 特殊逻辑：`OSD运营支持部` 且工时类型为“自研”的项目，内部订单按 `OSD运营支持部日常工作` 处理。

A5 当月工资计提

与 A4 同总额、同科目口径，但借方只到成本中心层级。

  • 借方：工资、社保、公积金费用按成本中心汇总，不拆内部订单。
  • 贷方：与 A4 同口径，汇总到应付职工薪酬及相关科目。
  • 日期：处理月份最后一天。
  • 校验：A5 借贷总额必须与 A4 保持一致。

A6 研发工时分摊调整

先冲回 A5 的非 OSD 费用，再按研发工时比例分摊到内部订单。

  • 贷方：原样冲回 A5 借方费用，科目不变、成本中心不变、内部订单为空。
  • 借方：按部门内项目工时占比分摊到内部订单，成本中心沿用原部门成本中心。
  • 工时口径：只取当月、只统计 `K>0`，`OSD运营支持部` 不参与分摊。
  • 校验：若非 OSD 部门没有可分摊工时，则不允许生成 A6；尾差自动回补到最后一个内部订单。

A7 年终奖计提

按成本中心计提年终奖，季度末采用累计口径并乘当月奖金系数。

  • 借方：统一为 `6601010003`，按成本中心展开。
  • 贷方：统一为 `2211010001`，每家公司只放 1 行汇总。
  • 金额规则：季度末取 1-当月累计奖金金额，再乘当月奖金系数；系数不追溯历史月份。
  • 文本/文件名：如 `计提2026Q1年终奖`、`计提Q1-Q2年终奖`。

A8 年终奖分摊

将 A7 的奖金费用按奖金期间对应的工时口径分摊到内部订单。

  • 科目：借贷双方都统一为 `6601010003`。
  • 贷方：冲回 A7 的非 OSD 奖金费用。
  • 借方：按内部订单分摊奖金，成本中心保持不变。
  • 工时口径：1月只看1月工时，2月只看2月工时，3/6/9/12月看1-当月累计工时。

A9 CO工单分摊

仅针对 2050，将待分摊费用按 CO 工单比例重新分配到指定订单。

  • 贷方：来自 `CO工单分摊.xlsx` 的待分摊费用，固定成本中心 `20502020`、固定内部订单 `9201856`。
  • 借方：按 `CO工单分摊` sheet 中 `G列不为0` 的订单，用 `E列实际成本借方` 作为比例分摊。
  • 特殊规则：最后一行加总仅用于校验，不参与分母；贷方 `O列` 反记账固定写小写 `x`。
  • 校验：A9 借贷必须平衡，且明细 `G列` 合计必须等于最后一行加总。

A10 研发费用分摊

将待分摊费用按公司内、部门内当月工时比例重新分配到研发内部订单。

  • 贷方：冲销 `待分摊费用YYMM.xlsx` 中原费用，记账码 `50`，科目取 `J列`，金额取 `L列`，成本中心/内部订单取 `S/U列`。
  • 借方：记账码 `40`，科目仍取原费用科目，按工时分摊到项目订单，成本中心沿用分摊后的成本中心。
  • 分摊口径：严格公司内分摊，默认部门内分摊，`OSD` 不参与；`HLD/LHD` 视为同一部门，且 `9201856` 不参与 HLD 分摊。
  • 特殊规则：`2050` 的 `20502050` 借方分摊视为 `20502060`；`2060` 的 `20602020` 若无部门工时，则改按整个耐数信息公司工时分摊。
校验主题 控制规则
基础数据完整性 工资单、Mapping 表、工时数据、年终奖数据、银行流水必须齐全；工时项目必须先全部匹配到内部订单，否则不允许继续处理。
公司隔离 所有工资、奖金、工时、银行流水、内部订单分摊均按公司严格隔离，不允许跨公司取数或分摊。
银行核对 工资、公积金、个税、社保四类项目分别核对；工资支持最多 5 笔代发工资组合匹配，差异结果直接反馈到输出文件。
借贷平衡 A1-A10 每一张凭证都单独检查借贷平衡，精确到分；涉及拆分的凭证自动做尾差回补，确保 SAP 导入前金额严格相等。
跨凭证逻辑 工资主链条对 A1-A4 重点科目执行交叉验证；A5/A6、A7/A8、A9、A10 则通过“原金额 = 冲回金额 = 分摊金额”保证前后衔接。

第二部分：本次数据示例与校验对应

以下示例均取自本次 202602 工资、202603 处理场景中的真实 Excel 数据。 每张凭证都配了对应的数据截图，并明确标出“哪个区域和哪个区域在做校验 / 汇总 / 分摊”。

A1 社保扣款凭证示例

左侧取工资整理文件总计行中的社保相关列，右侧取 3 月银行流水中的两条国库流水。

  • 校验关系：工资表社保七列合计 211,246.82 ↔ 银行流水社保行 O列 211,246.82。
  • 区分方式：同一批国库流水里，较小金额 19,469.94 属于个税，不计入 A1。

A2 公积金扣款凭证示例

左侧取工资整理文件中的公司/个人公积金，右侧取 2 月银行流水中的公积金付款行。

  • 校验关系：工资表 J+N = 94,812.00，银行流水为 91,162.00。
  • 本月特殊规则：这是已确认的 2050 / 202602 公积金特殊月份，按“工资表比银行大 3,650”处理。

A3 工资扣款凭证示例

劳务费逐行取工资表，工资与个税则分别去匹配代发工资组合和较小金额国库流水。

  • 对应关系 1：劳务费借方逐行取 D=劳务费 的 E列，并带出该行的 S/T。
  • 对应关系 2：非劳务薪资的 Q列汇总 形成 2211010001，非劳务的 O列汇总 形成 2221070000。
  • 校验关系：银行侧使用“代发工资组合 + 个税国库行”，不把社保国库行混入 A3。

A4 上月实际工资入账示例

左侧展示工资整理文件中已匹配好的成本中心/内部订单，右侧展示 A4 在凭证模板中的落地结果。

  • 借方来源：工资整理文件中非劳务行的费用列，按 成本中心 + 内部订单 汇总后入账。
  • 贷方来源：社保、公积金、个税、实发工资、其他项目等汇总值。
  • 本次结果：A4 借贷总额均为 862,411.56。

A5 当月工资计提示例

A5 和 A4 的金额口径一致，只是借方不再拆到内部订单，而是停留在成本中心层级。

  • 校验关系：A5 与 A4 使用相同的工资费用基础数据，只改变借方聚合维度。
  • 本次结果：A5 借贷总额均为 862,411.56，与 A4 完全一致。

A6 研发工时分摊调整示例

先看 3 月工时明细，再看核对表的分摊结果，最后看 A6 凭证如何把金额打到内部订单。

  • 校验关系：A5原金额 ↔ A6分摊金额合计，同一部门同一科目必须完全一致。
  • 工时口径：仅取 3月、仅统计 K>0、OSD 不分摊。
  • 本次结果：2050 的 A6 分摊总额为 725,265.05。

A7 年终奖计提示例

先取年终奖基础表中的部门金额，再取 3 月奖金系数，最后生成 A7 计提凭证。

  • 计算关系：2026-01~03累计奖金 × 3月系数 0.87 → A7 计提金额。
  • 本次结果：2050 的 A7 借贷总额均为 543,736.08。

A8 年终奖分摊示例

A8 在季度末看的是 1-3 月累计工时，不是只看单月工时；OSD 奖金不参与分摊。

  • 校验关系：A8 分摊前总额 = A8 分摊后总额；只是从成本中心口径改成“成本中心 + 内部订单”口径。
  • 差异来源：A8 不分摊 OSD，所以本次 A8 515,247.93 小于 A7 543,736.08。

第四部分：五类输出文件清单

脚本最终不是只输出一张表，而是按业务性质拆成五类文件，便于 SAP 导入、财务复核以及后续留档。

1. 工资整理文件

  • 按公司拆分输出，如 `2月工资单-整理后.xlsx`。
  • 包含 A/B 填充、Q 列校验、S 列成本中心、T 列内部订单以及银行核对结果。
  • 适合财务先做基础复核，再进入凭证导入阶段。

2. 薪酬凭证文件

  • “实际”文件：包含 A1-A4。
  • “计提”文件：包含 A5-A6。
  • 按公司分别输出，如 `2050总账凭证导入-实际202603薪酬.XLS`、`2050总账凭证导入-计提202603薪酬.XLS`。

3. 年终奖凭证文件

  • 单独输出年终奖计提与分摊文件，包含 A7-A8。
  • 文件名按月度或季度累计口径变化，例如 `计提202601年终奖`、`计提2026Q1年终奖`、`计提Q1-Q2年终奖`。
  • 适合单独导入、单独归档，不与工资计提文件混在一起。

4. CO工单分摊文件

  • 仅 `2050` 输出，包含 A9。
  • 例如 `CO工单分摊/2050总账凭证导入-CO工单分摊202603.XLS`。
  • 用于工资与奖金完成后，再做 CO 工单专项分摊。

5. 研发费用分摊文件

  • `2050`、`2060` 都会输出，包含 A10。
  • 例如 `2050总账-研发费用分摊2603.XLS`、`2060总账-研发费用分摊2603.XLS`。
  • 用于将待分摊费用按工时重新分配到研发内部订单。
